# 产品演示官网（product-demo-site）

**这个 Skill 的核心，是一镜到底地演示产品真实的界面和功能。**

- **首屏**：一句承诺，下面紧跟产品的一张真实截图。访客第一眼就看到产品长什么样。
- **主体**：一条滚动轨道，上面钉住一个舞台。舞台上摆着产品的**真实界面**，可以是截图，也可以是真实组件。镜头随滚动在界面之间移动、推近到某个功能，再配上高亮框和一句话标注。镜头走过的地方不会消失，最后一幕拉远，看到全貌。
- **字幕**：每幕两行。第一行是编号 + 这一幕演示了什么，第二行是访客认得出的痛点（hook）。
- **收尾**：一个按钮，加三条可以被转述的事实。

**要学的是样本的讲法，不是样本的长相。** 配色、字体、版式都来自**你的产品**。做出来如果像参考网站的翻版，就是失败。画布、点阵这些也只是某些产品自己的元素，产品里没有，就不要硬加。

技术实现基于 `template/`（React + Vite + Tailwind v4 + motion），所有时间轴写成数据，由滚动进度驱动。

## 用户需要给什么

只要两样：**这个 Skill + 产品资料**。产品资料是下面任意一种：

- 产品网址，线上环境或预发布环境都可以；
- 产品代码库路径。Agent 会读 README、DESIGN.md、路由，把产品在本地跑起来再截图；
- 附加材料，可选：参考样本的网址、想强调的卖点。

不要求用户填表。表由 Agent 自己填，用户只负责审。

## 工作流：同一个三角，四个阶段

```text
① 定义正确 ──────────────► 人工闸门 A ──► ② 实现 ──► ③ 验证正确 ──────► 人工闸门 B ──► ④ 上线 + 失败可恢复
   研究产品 → 起草 BRIEF.md     审一遍 brief      模板       test / verify / 看图    按标准验收       可回滚 · 问题回流
```

### ① 定义正确：Agent 自己研究，起草 brief

1. 复制模板：`cp -R <skill>/template ./site && cd site && pnpm install`
2. **研究产品**：
   - 有网址就直接用；只有代码库就先把产品跑起来。
   - 运行 `pnpm capture <网址> --pages <3 到 6 个关键页面>`，得到真实截图（`public/shots/`）、品牌配色和字体（`research/brand.json`）、页面标题和导航。
   - 再读一遍产品首页和文档的文字。
3. **起草 `BRIEF.md`**：按 [references/brief-template.md](references/brief-template.md) 自己填，规则见 [references/story-model.md](references/story-model.md)：
   - 一句话承诺；
   - 全片只演示一个具体的使用场景；
   - 场景表 5 到 7 幕，每幕对应产品的一个**真实界面**；
   - 品牌 token 从 `brand.json` 来；
   - 默认验收标准。
4. 准备 `capture.config.json`，为每一幕要推近的界面元素写好选择器。重新运行 `pnpm capture --config capture.config.json`，拿到真实元素的位置（`src/story/shots.json`）。

**人工闸门 A**：把 brief 交给用户审一遍，只问三件事：
- 一句话承诺对不对；
- 演示的场景是不是产品最想讲的；
- 有没有漏掉的验收标准。

用户确认之前，不写分镜代码。

### ② 实现：只改内容层

| 文件 | 改什么 |
| --- | --- |
| `src/styles.css` 的 `@theme` | **换成 `brand.json` 里产品自己的颜色和字体**（模板默认是中性灰占位） |
| `index.html`、`src/content/site.ts` | 标题、首屏（`hero.image` 用一张真实截图）、导航、收尾、页脚 |
| `src/story/script.ts` | 场景表 → `SCENES`；界面的摆放 → `BOARDS`；镜头 → `SHOTS`（推近时用 `shots.json` 里的真实元素位置） |
| `src/story/World.tsx` | 用 `Screen` 摆放真实截图，用 `Highlight` 和 `Callout` 指出功能 |
| `src/story/chat.ts` | 只有产品本身就是对话或 Agent 形态时才用，其他产品全部设为 `open: null` |

`src/engine/` 是引擎，一般不改。视觉规则见 [references/visual-rules.md](references/visual-rules.md)。

### ③ 验证正确：机器给证据，人做判断

```bash
pnpm test     # 时间轴不变量
pnpm build
pnpm verify   # 桌面和手机逐幕截图、字幕断言、溢出、控制台报错、减少动态效果、读屏大纲、遗留 TODO(brief)
```

`pnpm verify` 通过之后，**Agent 必须自己逐张看** `verify-output/` 里的截图，按 [references/verification.md](references/verification.md) 的看图清单检查。其中一条是：**和参考样本放在一起，看起来像不像翻版？** 发现问题就修，修完重新验证。

**人工闸门 B**：把预览地址和截图交给用户，请用户按验收标准逐条确认。

### ④ 上线与失败可恢复

见 [references/launch-and-recover.md](references/launch-and-recover.md)：
- 部署到能回滚的地方；
- 上线后在几种常见浏览器里抽检；
- 每一个线上问题都要回流成一条新的验收标准。

## 硬规则

- **主角是产品的真实界面。** 不手绘仿制界面，不编造数字。
- **品牌来自产品。** `@theme` 不能留着模板的灰色占位，也不能照搬参考样本的配色。
- 滚动进度是唯一的时钟，不用计时器推动叙事，往回滚动要能精确倒放。
- 时间轴只写在 `script.ts` 和 `chat.ts` 里。
- 减少动态效果时整段**替换**成静态版，每一幕都要能看到。
- 演示用的界面要么是截图，要么是加了 `inert` 的组件，不能出现看起来能点、实际点了没反应的控件。
- 页面不请求任何接口。
- 渐变用 `rgb()` 写死色值（Tailwind v4 的渐变会输出 `oklab()`，部分内置浏览器的旧内核不支持）。

## 什么时候不该用

- 产品没有可以演示的界面或流程（比如纯 API、纯内容站）：做普通的分区落地页。
- 用户要的是视频：用视频类 Skill，这里的分镜可以复用。

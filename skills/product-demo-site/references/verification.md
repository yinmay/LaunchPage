# 验证正确：自动检查 + 看图清单 + 人工验收

## 1. 自动检查（`pnpm test` / `pnpm build` / `pnpm verify`）

| 检查 | 由谁做 | 覆盖的默认 AC |
| --- | --- | --- |
| 时间轴分段连续、`beat` 落在本幕内、`nextStop` 能走完全程 | `pnpm test` | — |
| 字幕标题 ≤30 字、hook ≤40 字，key 唯一 | `pnpm test` | AC-01（部分） |
| 镜头关键帧有序、缩放不超过上限 | `pnpm test` | — |
| 类型检查、生产构建 | `pnpm build` | — |
| 桌面端和手机端逐幕截图，断言字幕对应的场景 | `pnpm verify` | AC-02 |
| 没有横向溢出 | `pnpm verify` | AC-03 |
| 隐藏大纲包含每一幕 | `pnpm verify` | AC-04 |
| 没有控制台报错 | `pnpm verify` | AC-05（部分） |
| 减少动态效果时每一幕都有静态版 | `pnpm verify` | AC-06 |
| 没有遗留的 `TODO(brief)`，包括 `@theme` 里的品牌占位 | `pnpm verify` | AC-07（部分） |

`pnpm verify` 默认会自己启动 `vite preview`。要检查已经部署的地址，用 `VERIFY_URL=<url> pnpm verify`。截图和 `report.json` 都在 `verify-output/` 里。

## 2. 看图清单（Agent 必须自己做）

自动检查通过后，逐张打开 `verify-output/*.png` 看。下面每一条都是自动检查抓不到、却真实出现过的问题：

- [ ] **残留噪点**：还没画出来的箭头露出一个点、零件提前闪现。
- [ ] **重叠和截断**：便签压住卡片，日志行超出卡片，盖章压住文字。
- [ ] **手机端折行**：编号「01 / 06」被折成两行，标题最后一个字单独掉到下一行，导航挤在一起。
- [ ] **构图**：推近时主体是否居中；有没有被 Agent 面板挡住；拉远时画板标题还认不认得出。
- [ ] **信息密度**：一幕里同时出现的新东西超过 5 个，就拆开节拍或者拆成两幕。
- [ ] **一致性**：对话面板说的和画布上画的是同一件事，编号和 AC 编号前后一致。
- [ ] **首屏**：5 秒内能不能说清是什么、给谁、点哪里；能不能看到产品的真实界面。
- [ ] **像不像翻版**：把首屏截图和参考样本的首屏并排放。配色、版式、标志性元素有没有照搬？有的话，回到 `research/brand.json` 重新取色。
- [ ] **真实性**：画面里每一个界面都是产品的真实截图或真实组件吗？推近的位置是不是对准了真实的元素？

发现问题就修，修完重新跑 `pnpm verify`，**再看一遍图**。

## 3. 人工验收（人工闸门 B）

交给用户的材料：

1. 预览地址或预发布地址；
2. `verify-output/` 里的截图（桌面 + 手机 + 减少动态效果）；
3. BRIEF.md 里的验收标准表，每条后面附上它的证据（截图文件名，或者「需要人工确认」）。

请用户在真实设备上按表逐条确认。至少包括一台手机，最好再加一个微信内置浏览器。用户确认通过后才上线。
